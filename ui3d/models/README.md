# Models

Drop a 3D model in this folder and the table will stand it on the matching card.

Nothing here is required. With the folder empty — which is how it ships — every card is the flat
rectangle it has always been and nothing is different. This is purely the door being left open.

## Naming

Files are matched to cards the same way card pictures are: lower case, punctuation ignored.

```
serra angel.g3db        that exact card
_creature.g3db          every creature with no model of its own
_artifact.g3db          every artifact, and so on
```

The fallbacks are `_creature`, `_land`, `_planeswalker`, `_artifact`, `_enchantment`, `_card`.
A card asks for its own name first, so four or five generic shapes dress a whole board and a
named model overrides one wherever you make it.

Try it now: copy `sample-statue.g3dj` to `_creature.g3dj` and every creature on the table stands
a stone obelisk on its card. Delete it and they stop. That file was generated by a script with no
modelling tool involved — see **Making one by hand** below.

## Formats

| Format | Animation | How you get one |
|---|---|---|
| `.g3db` | yes | Blender/Maya → FBX → [fbx-conv](https://github.com/libgdx/fbx-conv). The one to use |
| `.g3dj` | yes | The same thing as JSON. Readable, writable by hand, much larger |
| `.obj` | **no** | Export straight from any tool. Geometry only — no skeleton, so no animation |

glTF is **not** supported: libGDX reads it only through the separate `gdx-gltf` library, which
Forge does not ship, and this project does not download anything.

## Size, facing, animation

Three things you do not have to think about:

- **Size.** A model is measured when it loads and scaled so it stands `Models.FIGURE_H` high
  (0.95 — a card is 1.0 × 1.4). Export in metres, centimetres or furlongs; it arrives the right
  size.
- **Facing.** It is turned to match the card it stands on, so it faces its owner and turns with
  the card when it taps.
- **Animation.** A model with animations gets an `AnimationController` and its first animation on
  a loop, started at a random offset so six copies of the same token are not a chorus line. One
  without animations is simply still.

Model the figure standing on the ground at the origin, facing **+Z**, Y up.

## What the engine can do beyond this

libGDX 1.14.2 ships whole inside Forge's mobile jar, so everything below is available today
without adding a dependency. What is missing is not the engine, it is the art and the work:

- **Skeletal animation** — `AnimationController`, blended transitions between clips
- **Particles** — `g3d.particles`, with effects authored in libGDX's Flame editor, or billboards
  driven in code through `DecalBatch`
- **Shadows** — `DirectionalShadowLight` and the shadow-map shader; the table currently has none
- **Custom shaders** — `ShaderProgram` and a custom `Shader`, for anything the default one cannot
  do: dissolves, rim light, a card burning away as it dies
- **Post-processing** — `FrameBuffer`, so bloom, colour grading and glow passes are possible

### The real limits

- **No assets and no artist.** Everything on this table is generated at startup from boxes and
  procedural textures, which is why a fresh clone runs with nothing downloaded. Real models mean
  real files in git.
- **No fbx-conv in the toolchain.** Adding `.g3db` support to the workflow means adding that
  binary; `.obj` and `.g3dj` need nothing, which is why the sample is `.g3dj`.
- **Draw calls.** Every figure is one more instance in the scene's single `ModelBatch`. A
  four-player board can already be 150 instances; a few hundred more is fine, tens of thousands
  is not.
- **Bone count.** The default shader carries 12 bones per mesh unless it is reconfigured, so a
  heavily rigged character needs `DefaultShader.Config` changed.

## Making one by hand

`.g3dj` is JSON: `meshes` (vertices, normals, triangle indices), `materials`, `nodes`. A script
can write one directly, which is how `sample-statue.g3dj` was made — a tapered obelisk, 84
vertices, flat-shaded. For simple carved shapes that is often less work than a modelling tool,
and it stays in version control as text that can be diffed.

## Switches

| Property | Effect |
|---|---|
| `-Dforge.ui3d.models=<path>` | Read models from somewhere else |
| `-Dforge.ui3d.models=off` | Do not look for models at all |
| `-Dforge.ui3d.figures=false` | Keep the models loaded but stop standing them on cards |
