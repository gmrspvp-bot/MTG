# Models

Drop a 3D model in this folder and the table will stand it on the matching card.

Nothing here is required. With the folder empty — which is how it ships — every card is the flat
rectangle it has always been and nothing is different. This is purely the door being left open.

> ### This is a work in progress
>
> Two cards' worth of models exist (Athreos, both forms) and they have been looked at in the demo
> and in a real game. Everything else here is scaffolding that works but has barely been used.
>
> Expect to hit rough edges, and expect this document to be wrong in places as the thing settles:
>
> - **Hand-authored geometry is the only proven path.** No `.g3db` from a modelling tool has been
>   loaded yet, so fbx-conv, skeletons and animations are untested in practice even though the
>   loader handles them.
> - **One model per card per form.** There is no way to vary a figure by anything else — not by
>   counters, not by whether it is tapped, not by power.
> - **Nothing is animated.** The ferry effect for Athreos's ability is not built; effects like
>   that have to be drawn by the table, not stored in the model file (see *Animation* below).
> - **No art budget.** Every model here is maths in a Python script. That is a deliberate choice
>   for now, not a limitation of the format.
>
> If you add a model and it looks wrong, say so rather than working around it. The conventions
> below are young enough to change.

## Naming

Files are matched to cards the same way card pictures are: lower case, punctuation ignored.

```
serra angel.g3db        that exact card
_creature.g3db          every creature with no model of its own
_artifact.g3db          every artifact, and so on
```

The fallbacks are `_creature`, `_land`, `_planeswalker`, `_artifact`, `_enchantment`, `_card`.
A card asks for its own name first, so four or five generic shapes dress a whole board and a
named model overrides one wherever you make it.

### Cards that are two different things

A permanent that is only sometimes a creature can have a model for each state. While the card is
a creature the table asks for `<name> awake` first:

```
athreos god of passage.g3dj          below devotion 7 — a crystal cocoon
athreos god of passage awake.g3dj    devotion 7+      — the ferryman himself
```

With no `awake` file the plain name is used for both, which is what every other card does.

This is wired to one thing only: whether the card **is a creature this frame**. That covers the
Theros gods, a crewed vehicle and an animated manland, and nothing else. The figure re-resolves
the moment the state flips, and both forms stay cached while the card is on the table, so a god
crossing its devotion back and forth does not reload anything.

Build both forms to the **same overall height**. The loader normalises on the Y bounding box, so
a short dormant form would be scaled up to the same size as the tall one and the swap would jump.

Try it now: copy `sample-statue.g3dj` to `_creature.g3dj` and every creature on the table stands
a stone obelisk on its card. Delete it and they stop. That file was generated by a script with no
modelling tool involved — see **Making one by hand** below.

## Formats

| Format | Animation | How you get one |
|---|---|---|
| `.g3db` | yes | Blender/Maya → FBX → [fbx-conv](https://github.com/libgdx/fbx-conv). The one to use |
| `.g3dj` | yes | The same thing as JSON. Readable, writable by hand, much larger |
| `.obj` | **no** | Export straight from any tool. Geometry only — no skeleton, so no animation |

glTF is **not** supported: libGDX reads it only through the separate `gdx-gltf` library, which
Forge does not ship, and this project does not download anything.

## Size, facing, animation

Three things you do not have to think about:

- **Size.** A model is measured when it loads and scaled so it stands `Models.FIGURE_H` high
  (0.95 — a card is 1.0 × 1.4). Export in metres, centimetres or furlongs; it arrives the right
  size.
- **Facing.** Every figure faces the middle of the table — which is to say the other players.
  The facing comes off the seat, not off the card, so a tapped card does not turn its figure
  sideways. (It used to take the card's yaw, and since a card is turned so its owner can read it,
  every figure stood with its back to the game.)
- **Animation.** A model with animations gets an `AnimationController` and its first animation on
  a loop, started at a random offset so six copies of the same token are not a chorus line. One
  without animations is simply still. **Only the first clip, only on a loop** — there is no way
  to trigger a clip on a game event, so a model cannot animate when its ability resolves. An
  effect like that has to be drawn by the table, the way the phasing ghost and the damage pips
  already are.

Model the figure standing on the ground at the origin, facing **+Z**, Y up. The table turns it
from there, so +Z is "towards the enemy" once it is placed.

## What the engine can do beyond this

libGDX 1.14.2 ships whole inside Forge's mobile jar, so everything below is available today
without adding a dependency. What is missing is not the engine, it is the art and the work:

- **Skeletal animation** — `AnimationController`, blended transitions between clips
- **Particles** — `g3d.particles`, with effects authored in libGDX's Flame editor, or billboards
  driven in code through `DecalBatch`
- **Shadows** — `DirectionalShadowLight` and the shadow-map shader; the table currently has none
- **Custom shaders** — `ShaderProgram` and a custom `Shader`, for anything the default one cannot
  do: dissolves, rim light, a card burning away as it dies
- **Post-processing** — `FrameBuffer`, so bloom, colour grading and glow passes are possible

### The real limits

- **No assets and no artist.** Everything on this table is generated at startup from boxes and
  procedural textures, which is why a fresh clone runs with nothing downloaded. Real models mean
  real files in git.
- **No fbx-conv in the toolchain.** Adding `.g3db` support to the workflow means adding that
  binary; `.obj` and `.g3dj` need nothing, which is why the sample is `.g3dj`.
- **Draw calls.** Every figure is one more instance in the scene's single `ModelBatch`. A
  four-player board can already be 150 instances; a few hundred more is fine, tens of thousands
  is not.
- **Bone count.** The default shader carries 12 bones per mesh unless it is reconfigured, so a
  heavily rigged character needs `DefaultShader.Config` changed.

## Making one by hand

`.g3dj` is JSON: `meshes` (vertices, normals, triangle indices), `materials`, `nodes`. A script
can write one directly, which is how `sample-statue.g3dj` was made — a tapered obelisk, 84
vertices, flat-shaded. For simple carved shapes that is often less work than a modelling tool,
and it stays in version control as text that can be diffed.

**`make-athreos.py` is the worked example.** Run it with any Python 3 and it rewrites both
Athreos models in place:

```
python ui3d\models\make-athreos.py
```

It carries the primitives that turned out to be worth having — a lathe with per-angle fold
modulation (how the robe gets cloth folds), tapered tubes, partial torus arcs (the crook's hook),
flat-shaded faceted columns (how the cocoon reads as crystal rather than as a green egg), and
extruded outlines from quadratic curves. Copy it for the next card rather than starting over.

Two things it shows that are easy to get wrong:

- **Normals decide whether a surface looks right.** Smooth-shaded surfaces take their normals
  from the generated grid, not from the un-folded shape, or the folds shade as though they were
  not there. Stone and crystal are flat-shaded with per-face normals instead, which is what makes
  the facets catch light as hard edges.
- **`opacity` on a material** becomes a libGDX `BlendingAttribute`, which is how the cocoon is
  translucent enough to show him folded up inside it.

Check a generated file before trusting it: every part's indices must be in range and a multiple
of three, and every `materialid` on the node must exist in `materials`. A model that fails those
loads as nothing, silently, and the card just stays flat.

## Switches

| Property | Effect |
|---|---|
| `-Dforge.ui3d.models=<path>` | Read models from somewhere else |
| `-Dforge.ui3d.models=off` | Do not look for models at all |
| `-Dforge.ui3d.figures=false` | Keep the models loaded but stop standing them on cards |
